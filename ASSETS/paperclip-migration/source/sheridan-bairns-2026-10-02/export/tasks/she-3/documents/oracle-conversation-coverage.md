## Can earlier conversations be used?
Yes, if saved in accessible Paperclip records or supplied through an authorized transcript/source. Successful API reads in this run establish access to stored comments, documents and review answers; this does not depend on recalling them from model memory. OpenAI's [conversation-state documentation](https://developers.openai.com/api/docs/guides/conversation-state) describes providing prior messages or persisting conversation state. It does not establish that this Paperclip installation automatically imports every previous Codex or ChatGPT chat.

A durable reference can incorporate retrieved conversations by retaining speaker, date, original record link/ID and exact scope; separating founder statements from agent proposals; mapping claims to the source; retaining conflicts and later corrections; and issuing a new reference revision with a change reason. Founder-intent conflicts should go through Chief of Staff for founder review. This is a proposed incorporation method, not a claim that missing history has already been imported.

Concrete provenance example: the 27 September website-direction answer asks for a reasoned audit trail. The v0.3 review maps that direction to C2/C3/C6/C8/C12 and treats the record format as an inference. Assuming the saved `local-board` response represents the founder direction, it supports intended positioning; it does not support a guarantee of protection after a bad outcome. This preserves the distinction between source statement, interpretation and unsupported extension.
